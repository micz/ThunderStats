# ThunderStats — Internationalization (i18n)

## Overview

ThunderStats uses the standard **WebExtension i18n API** combined with a small resolver (`statslib/mzts-i18n.js`) that replaces `__MSG_key__` placeholders in the rendered DOM.

---

## Rules for Agents

1. **Edit only `public/_locales/en/messages.json`.** All other locales are managed on Weblate (`https://micz.it/weblate/thunderstats/`) and arrive as Weblate commits.
2. **Do not edit `LANG.md`.** It is the list of locales shipped in the XPI. The author adds a locale there only when its translation is ready to ship.

---

## Locales

- Source of truth for existing locales: the folders in `public/_locales/` (one `messages.json` each).
- Source of truth for **shipped** locales: `LANG.md` (one locale code per line). `build.js` excludes from the XPI every `_locales/<code>` folder not listed there, so a locale can exist in the repo (e.g. while being translated) without being shipped.
- `en` is the reference locale and the manifest `default_locale`. Missing keys fall back to `en`.
- Translator credits are listed in `README.md`.

Each `messages.json` follows the WebExtension format:
```json
{
  "keyName": {
    "message": "Translated string",
    "description": "Optional context for translators"
  }
}
```

---

## How It Works

### 1. In templates: `__MSG_key__` placeholders

Vue templates contain literal `__MSG_key__` strings (text nodes and attributes). After mounting, the app calls `i18n.updateDocument()`, which walks the DOM via XPath and replaces each placeholder with its translation.

```js
import { i18n } from "@statslib/mzts-i18n.js";

i18n.updateDocument();                // localize the whole document
i18n.updateString("__MSG_Mails__");   // localize a single string
```

`mzts-i18n.js` exports the object `i18n` with:
- `updateDocument(options = {})` — sets `keyPrefix` (default `"__MSG_"`) and optional `extension`, then calls `updateSubtree(document)`
- `updateSubtree(node)` — replaces placeholders in text nodes and attributes under `node`
- `updateString(string)` — regex `__MSG_(.+?)__`; resolves each key with `messenger.i18n.getMessage(key)` and leaves the placeholder unchanged if the key is missing

Content rendered after `updateDocument()` runs (e.g. inside `v-if` blocks shown later) is not localized automatically; components re-run `i18n.updateDocument()` when needed.

### 2. In JavaScript: direct API calls

```js
browser.i18n.getMessage('keyName')
```

Used for strings built at runtime (chart labels, context menu items, etc.).

---

## Adding a New Translation Key

1. Add the key to `public/_locales/en/messages.json` only.
2. Use it as `__MSG_yourKey__` in templates or `browser.i18n.getMessage('yourKey')` in JavaScript.
